# category-copy-rules

쇼핑숏츠 7장 슬라이드 카피를 카테고리에 맞게 생성할 때 참고하는 규칙. 원본: `02_Knowledge_상세규칙.md.md` (카테고리별 7장 슬라이드 구성 / 시즌 캘린더 / 글자수 / A·B 카피 섹션).

## 시즌 캘린더 (카피 키워드 반영용)

| 월 | 시즌 키워드 |
|---|---|
| 1~2월 | 겨울건조 / 설날 |
| 3~4월 | 봄환절기 / 새학기 |
| 5~6월 | 어버이날 / 여름준비 |
| 7~8월 | 여름휴가 / 자외선 |
| 9~10월 | 가을환절기 / 추석 |
| 11~12월 | 수능 / 블프 / 크리스마스 |

카피 작성 시 현재 월에 맞는 시즌 키워드를 헤드라인이나 본문에 자연스럽게 반영한다.

## 카테고리별 7장 슬라이드 구성

각 카테고리는 아래 7단계 구조를 따른다. 순서는 고정.

| 카테고리 | 1.후킹 | 2 | 3 | 4 | 5.상품평재가공 | 6.특가 | 7.CTA |
|---|---|---|---|---|---|---|---|
| 화장품 | 후킹 | 피부타입+성분 | 효능/텍스처 | 인증 | 상품평재가공 | 특가 | CTA |
| 주방용품 | 후킹 | 추천대상+기능3 | 소재/안전+사용법 | 용량+세척 | 상품평재가공 | 특가 | CTA |
| 생활가전 | 후킹 | 추천대상+기능 | 스펙+인증 | 사용시나리오+설치 | 상품평재가공 | 특가 | CTA |
| 생활용품 | 후킹 | 추천대상+기능3 | 소재/안전+사용법 | 사이즈+활용팁 | 상품평재가공 | 특가 | CTA |
| 자동차용품 | 후킹 | 차종+기능 | 설치법+호환 | 안전인증+전후비교 | 상품평재가공 | 특가 | CTA |
| 식품(가공) | 후킹 | 추천대상+특징3 | 원재료/인증+맛 | 조리법+보관법 | 상품평재가공 | 특가 | CTA |
| 식품(신선) | 후킹 | 추천대상+특징3 | 원재료/인증+맛 | **보관팁&먹는법** | 상품평재가공 | 특가 | CTA |
| 기타 | 화장품/주방용품 템플릿을 유연하게 적용 | | | | | | |

- **식품(신선) 분기**: `resolveFoodCategory`로 자동 판별. 신선식품이면 4번 슬라이드를 "보관팁&먹는법"으로 대체하고, 조리/전자레인지 관련 언급은 배제한다.
- **기타 카테고리**: 화장품 또는 주방용품 템플릿 중 상품 특성에 맞는 쪽을 유연하게 적용한다.

## 글자수 제한

- 헤드라인: 16자 이내
- 본문: 60자 이내
- 태그: 10자 이내
- 음성 나레이션(`narration`, 선택 필드): 슬라이드당 한 문장, **30자 이내** (아래 "화면·음성 문장 분리" 참고)
- 마무리 나레이션(`outro`): 슬라이드당 한 문장, 16자 이내 (아래 "마무리 나레이션" 참고)
- 성분명·브랜드명만 예외적으로 영어 표기 허용 (그 외 한글 사용)

## 후킹(1번 슬라이드) 규칙

1번 슬라이드의 headline·body와 썸네일 A/B에 적용한다. 음성으로는 headline이 나가므로 headline이 특히 중요하다.

- **문제 제기와 해결책(제품·구성)을 한 문장에 같이 말하지 않는다.** (안 되는 예: "속당김엔 토너·에멀전 세트")
- **결론을 먼저 말하지 않는다.** 궁금증을 남기고 다음 슬라이드로 넘긴다 — 1번에서 제품의 장점·특징·구성을 다 풀지
  않는다 (그건 2번 이후 슬롯의 몫이다).

## 헤드라인 앵글 로테이션 (1번 슬라이드)

매번 같은 구조로 쓰지 않는다. 상품마다 다른 각도를 쓴다.

> pending에 `fullScript`(사용자 완성 대본)가 있으면 이 섹션 대신 아래 "사용자 제공 완성 대본 처리"를
> 따른다 — 후킹은 대본 원문 첫 부분을 쓰고, 앵글을 새로 고르지 않는다.

- **대비형**: 제품 특성의 대비로 연다 (예: "다른 토너랑 다르게…"). 타사·타제품이 더 못하다는 식의 우열 주장은 금지.
- **공감형**: 구체적인 상황을 묘사한다 (예: "세안하고 나면 금세 당기죠").
- **반전형**: 선입견을 뒤집는다 (예: "토너는 다 똑같다고요?").
- 쓰기 전에 `public/completed/`에서 최근 completed JSON 3개(파일명 내림차순)를 Read로 열어 1번 headline의
  앵글·구조를 확인하고, 그것들과 **다른 앵글**을 고른다 (열 수 없으면 위 세 가지 중 하나를 고른다).
- 앵글이 달라도 사실 근거 규칙(이미지·상품평으로 확인되는 것만)은 그대로 적용한다.

## AI스러운 표현 금지 (headline·body·outro·썸네일 공통)

- 금지어: "다양한", "완벽한", "많은 분들이"
- **3개 나열식 구조 금지** — 항목을 셋 이상 줄줄이 늘어놓는 문장 ("A, B, 그리고 C까지" 식). 나열은 2개까지.
- **추상적 마무리 금지** — 구체 정보 없이 분위기로 끝내는 문장 ("~한 시간 되세요", "~한 하루 보내세요" 류).

## 근거 기록 (저장 전 필수 — 자가 QA 대체)

"위반 0건"을 스스로 선언하는 방식은 쓰지 않는다 (모델이 자기 카피를 채점하면 위반을 놓친다 — 2026-09-21 확인).
대신 **사실로 읽히는 문장마다 근거 인용을 `qa.evidence`에 남겨서 사람이 빠르게 대조**할 수 있게 한다.

- **대상**: 성분·수치·구성·용량·제형/사용감·사용법·인증·가격·후기 내용처럼 사실로 읽히는 문장 (headline·body·outro·썸네일).
  질문형 후킹처럼 사실 주장이 없는 문장은 대상이 아니다.
- **기록 형식**: 한 항목에 한 주장. `slide`(번호), `field`(headline/body/outro/thumbnailA/thumbnailB), `claim`(카피에서 주장하는
  내용), `source`(`product_N` = N번째 제품 이미지 / `review_N` = N번째 상품평 이미지 / `productName`), `quote`(상품평이면
  **원문 그대로**, 제품 이미지면 이미지에 보이는 글자나 장면).
- **근거를 못 찾은 문장**은 쓰지 않는다. 쓴 뒤에 근거 없음을 알게 됐으면 그 문장만 **1회** 근거 있는 사실로 고쳐 쓴다.
  그래도 근거가 없으면 그대로 저장하되 `qa.unverified`에 적는다 — 근거가 있는 것처럼 꾸며 적지 않는다.
- 근거 인용은 표현이 아니라 **사실 검증용**이다 (위 "제형·사용감은 인용 강제" 참고): 카피의 낱말이 원문과 달라도, 같은 사실이면 된다.
- 화장품 5번(상품평 재가공)은 리뷰 표의 항목("보습력: 속건조/당김이 완화돼요" 등)을 그대로 인용한다.

## 금지 표현 (절대금지확인)

표시광고법상 객관적 근거 없이 쓰면 공정위 규제 대상이 될 수 있는 절대적/최상급 표현은
헤드라인·본문·썸네일 문구 어디에도 쓰지 않는다. (`02_Knowledge_상세규칙.md.md`의
체크리스트에 "절대금지확인" 항목명은 있으나 구체적 목록이 문서화돼 있지 않아, 이
스킬에 명문화한다 — 2026-07-XX 진단.)

| 금지 표현 | 대체 표현 |
|---|---|
| 최저가 | 특가 |
| 역대급 | 인기 많은 |
| 최다판매 | 인기 많은 |
| 1위 | 인기 |
| 최고 | 아주 좋은 |
| 베스트 | 인기 |

`server.py`의 `_filter_prohibited_words()`가 나레이션/자막(TTS·captions.json) 텍스트에
한해 사후 안전망으로 같은 목록을 필터링하지만, headline/body(화면 PNG 텍스트)는 이
필터를 거치지 않는다 — 카피 생성 단계(이 스킬)가 사실상 유일한 방어선이므로 반드시
지킨다.

## 효능·결과 단정 금지 (헤드라인·본문)

헤드라인·본문에서 효능이나 사용 결과를 단정하지 않는다. 마무리 나레이션(`outro`)에는 이미 같은 규칙이 있다.
**5번 슬라이드(상품평 재가공)는 예외** — 실제 리뷰 내용을 옮기는 슬롯이라 리뷰에 있는 표현을 재가공해도 된다
(리뷰 이미지가 없으면 지어내지 않는다는 위 규칙은 그대로).

- **쓰지 않는 것**: 결과·효과가 확정된 것처럼 말하는 문장 (예: "속당김을 완화해요", "겉돌지 않고 쏙 흡수돼요",
  "피부가 촉촉해져요", "확실한 차이") 과 개인 체험담 어투.
- **대신 쓰는 것**: 제품 이미지에서 확인되는 사실 — 구성·용량·성분 표기·제형/질감·사용 방법·추천 대상.
  질감·사용감은 "결과"가 아니라 제품 특성으로 쓴다 (예: "묽은 제형이에요", "손바닥에 덜어 발라요").
- **제형·사용감 서술은 인용 강제**: 제형·질감·사용감을 쓰기 전에 상품평 원문에서 관련 문장을 **글자 그대로** 찾아
  먼저 적는다(작업 메모, completed JSON에는 넣지 않는다). 쓰려는 서술이 그 인용문과 어긋나거나 인용할 문장이 없으면
  쓰지 않는다. 리뷰어가 **다른 제품**을 두고 한 말(예: 이전에 쓰던 제품의 질감)을 이 제품 서술로 옮기지 않는다.
  상품평 이미지가 없으면 제품 이미지에 직접 보이는 것만 쓰고, 그것과 어긋나는 서술은 하지 않는다.
  인용 강제는 **사실 검증용**이지 원문 낱말을 그대로 쓰라는 뜻이 아니다 — 사실(형태 유지·점도·발림성 등)은 유지하고
  **표현만** 소비자 친화적인 말로 바꿔 쓴다 (예: '콧물 제형' → '탱글한 젤 타입', '쫀쫀하게 형태가 유지되는'). 단, 원문에 없는 성질을 덧붙이지 않는다.
- **화장품 4번(인증) 슬라이드**: 전후 효과·체감 결과는 쓰지 않는다. 제품 이미지에 **실제로 보이는** 인증마크·
  시험/테스트 결과 표기 등 검증 가능한 사실만 쓴다 (표기된 그대로, 없는 인증·수치를 만들지 않는다). 이미지에서
  인증·테스트 표기를 확인할 수 없으면 지어내지 말고, 이미지로 확인되는 다른 사실(성분 표기·용량·제형·사용법)로 채운다.
- **화장품 6번(특가) 슬라이드**: 가격·할인율·특가 여부는 이미지에 실제로 보이는 정보만 쓴다. 이미지에 가격 정보가
  없으면 "가격/특가는 링크에서 확인해보세요"처럼 확인 방법만 안내하고, 특가 진행 중이라거나 가격·할인율·기간을
  지어내지 않는다.

## 화면·음성 문장 분리 (`narration`, 선택 필드)

`headline`은 화면 PNG에 그대로 찍히는 짧은 문구(16자 이내)이고, 지금까지는 이 headline을 그대로
구어체로 다듬어 음성·자막에도 재사용했다 — 그래서 화면 문구와 음성 문구가 사실상 같은 문장이 됐다.
`narration` 필드를 쓰면 **화면용 headline과 음성용 문장을 다르게** 쓸 수 있다.

> pending에 `fullScript`가 있으면 아래 글자수·재작성 규칙은 적용하지 않는다 — narration은 대본 원문
> 그대로 쓴다 ("사용자 제공 완성 대본 처리" 참고).

- **선택 필드다.** 안 쓰면 기존과 100% 동일하게 동작한다(서버가 headline을 구어체로 변환해 그대로 씀) —
  기존 completed JSON(narration 필드 없음)은 그대로 유효하다.
- 쓸 때는 headline과 **같은 사실을, 다른 문장으로** 말한다 — headline을 그대로 옮기거나 어미만 바꾸지
  않는다(그러면 분리하는 의미가 없다). 예: headline "55입, 550g 구성이에요" → narration
  "하루 한 번, 55일치가 들어있어요"(같은 사실을 다른 표현으로).
- 길이: 30자 이내, 구어체 완결문("~해요/~예요/~돼요" 등)으로 끝낸다. 문장을 중간에 자를 일이 없도록
  처음부터 완결된 한 문장으로 쓴다.
- 근거 규칙(위 "근거 기록", "효능·결과 단정 금지")은 headline과 동일하게 적용한다 — narration도 사실
  주장이면 `qa.evidence`에 근거를 남긴다.
- `narration`과 `outro`는 이어 붙여 한 번에 재생되므로(아래 "마무리 나레이션" 참고) **서로 같은 말을
  반복하지 않는다.**

## 마무리 나레이션 (`outro`)

각 슬라이드에 영상 음성·자막 끝에 덧붙일 **마무리 한 문장**(`outro`)을 함께 쓴다. 화면 PNG에는 안 나오고
영상의 나레이션/자막에만 쓰인다. 서버(`server.py`)는 이 값이 규칙에 맞으면 그대로 쓰고, 없거나 규칙에
어긋나면 고정 문구 풀로 대체한다 — 그래도 애초에 규칙대로 써야 상품에 맞는 나레이션이 나온다.

> pending에 `fullScript`가 있으면 `outro`는 **비워둔다**(만들지 않는다) — 대본 자체가 이미 완결된
> 흐름이라 AI가 마무리 문장을 더 붙이면 "원문에 없는 문장을 추가"하게 된다. 서버도 `scriptSource`가
> `"user"`면 이 슬롯에 고정 풀 문구를 채우지 않는다("사용자 제공 완성 대본 처리" 참고).

> **메모 (2026-09-21, 2026-09-23 갱신)**: `outro`는 **음성 나레이션 뒤에 이어 붙는 문장**이다. 서버가
> 음성·자막으로 내보내는 문장은 "나레이션 본문(`narration`이 있으면 그것, 없으면 headline 요약 — 끝에
> '~이에요/예요'가 붙음) + `outro`"이고, **body는 화면 텍스트일 뿐 음성에 나가지 않는다**(narration도
> headline도 없을 만큼 짧은 경우에만 body 첫 구절이 보충으로 붙는 예외가 있다). 그래서 `outro`의 문맥
> 연속성과 단어 중복 여부는 **body가 아니라 나레이션 본문(narration 우선, 없으면 headline) 기준**으로
> 맞춘다 — body를 이어 받는 말로 쓰지 않는다.

- 슬라이드당 정확히 한 문장, **16자 이내**, 구어체 종결("~해요/~예요/~세요")로 끝낸다.
- 역할: **1번 슬라이드는 궁금증**(호기심을 여는 말), **7번(마지막)은 행동유도**(링크 확인 등),
  **2~6번은 공감과 혜택을 번갈아**(2번 공감, 3번 혜택, 4번 공감, 5번 혜택, 6번 공감).
- 해당 슬라이드의 **나레이션 본문**(narration이 있으면 narration, 없으면 headline)과 **같은 말을
  반복하지 않는다** — 이미 앞에 나온 표현을 되풀이하면 안 된다(예: narration이 "지금 바로
  확인해보세요"면 outro에 "확인해보세요"를 또 쓰지 않는다). body와 겹치지 않게도 쓴다.
- 7개 `outro`가 서로 **모두 달라야** 하고, 다른 상품에도 그대로 붙여넣을 수 있는 범용 문구보다 이 제품의 특징
  (이미지에서 확인한 것)에 맞는 말을 우선한다.
- 카테고리가 식품/식품_신선이면 "써보다/사용하다" 대신 "먹다/드시다"류 어휘를 쓴다.
- **쓰지 않는 것 (표시광고 리스크 — 위 "금지 표현" 표에 더해 적용)**:
  - 근거 없는 인기·판매량·후기 주장 ("많은 분들이 좋아하세요", "다들 쓰는", "완판")
  - 근거 없는 긴급성·마감 주장 ("서두르세요, 곧 끝나요", "마감 임박", "선착순")
  - 효과·결과 보장 ("후회 없을 거예요", "확실해요", "무조건", "100%", "반드시")
  - 인증·수상·검증 주장 ("인증된 제품이에요") — 이미지에서 확인되는 인증도 outro에는 쓰지 않는다
  - 과장 감탄 ("진짜 대박이에요") 및 최상급 표현
- 효능·결과를 단정하거나 체험담처럼 쓰지 않는다 (예: '~덜었어요', '~반가워요' 같은 개인 체험 서술 금지)
  - 근거 없는 시점 유도 금지 (예: "지금이 좋은 타이밍이에요", "지금이 기회예요").
  - 체감·평가 어투('~편해요', '~좋아요')는 쓰지 않고 '~이에요/예요' 객관 서술로 쓴다
    (예: "선물하기 좋아요" → "선물용 구성이에요").
- 리뷰 이미지가 없으면 후기를 암시하는 outro도 쓰지 않는다.

## A/B 카피 2안 규칙

- 모든 카피는 A안/B안 2가지를 필수로 생성한다.
- 카테고리 키워드 교차검증을 수행: 카피 내용이 해당 카테고리 핵심 키워드와 일치하는지 확인.
- 불일치가 발견되면 **해당 안(A 또는 B)만** 재생성하고, 나머지 안은 유지한다.
- 검증을 통과한 A/B 2안을 최종 출력한다.
- **썸네일 A/B(`thumbnailA`/`thumbnailB`)**: 별도 카테고리 템플릿을 쓰지 않는다. 1번 슬라이드
  (후킹) 헤드라인을 어투나 강조점만 다르게 살짝 변형한 2개 버전을 그대로 쓴다 — 아래
  "비동기 카피 생성 요청 처리" 5단계의 스키마 참고.

## 사용자 제공 완성 대본 처리 (`fullScript`)

`public/pending/{requestId}.json`에 `fullScript`(사용자가 STEP1에 붙여넣은 완성 대본 원문, 문자열)가
있으면, 아래 절차로 **그 대본을 7개 슬라이드에 배분**한다 — 이 절차는 "카피를 새로 쓰는" 것이 아니라
"이미 확정된 원문을 옮겨 담는" 작업이다. 이미지·리뷰는 사실 검증(대조)에만 쓰고, 카피 창작에는 쓰지 않는다.

1. **문장 단위로 나눈다.** 마침표·물음표·느낌표·사용자가 넣은 줄바꿈만 경계로 쓴다. 글자수로 기계적으로
   n등분하지 않는다.
2. **7개 슬롯(위 "카테고리별 7장 슬라이드 구성" 표)에 내용 기준으로 매핑한다** — 슬라이드 번호 순서대로
   기계적으로 나누지 않고, 각 문장이 어느 슬롯 역할(후킹/추천대상+기능/사용법/구성/후기재가공/특가/CTA)에
   해당하는 내용인지로 배정한다. 원문의 **문장 순서는 그대로 유지**한다(슬롯을 건너뛰며 순서를 바꾸지 않음).
   - **재분배를 먼저 시도한다**(2026-09-24 추가 — 실측: 닥터지 대본에서 후기 문장 2개가 5번에 다 몰리고
     6번이 완전히 빔). 한 슬롯에 배정될 문장이 2개 이상이고, 그중 뒤쪽 문장이 바로 다음 슬롯(대응 문장이
     0개인 슬롯)으로 옮겨도 원문 순서가 깨지지 않으면, 역할 이름이 정확히 일치하지 않더라도 그 문장을
     다음 슬롯으로 옮긴다 — 역할 이름은 "이 위치엔 대략 이런 내용이 온다"는 가이드일 뿐, 원문에 실제로
     있는 문장을 7슬롯에 최대한 고르게 나눠 담는 것이 우선이다(예: 특가 언급이 없는 6번에, 5번에 몰릴
     뻔했던 두 번째 후기 문장을 대신 배정 — "후기를 더 살펴보라"는 확인 유도는 6번 자리에서도 자연스럽다).
     재분배 후에도 다음 항목은 그대로 적용한다:
   - **문장이 7개보다 적음**: 한 문장이 두 슬롯에 걸친 내용이면(쉼표·접속사로 이어진 절 단위) 그 경계에서만
     나눠 두 슬라이드에 배분한다. 재분배로도 특정 슬롯에 대응하는 문장이 전혀 없으면, **그 슬롯을 위해 새
     문장을 만들지 않는다** — 3번(D)에서 "부족" 상태로 표시한다.
   - **문장이 7개보다 많음**: 재분배 후에도 같은 슬롯에 문장이 여럿 남으면 원문 순서 그대로 이어붙여 그
     슬라이드의 `narration`에 담는다(문장을 버리지 않는다). 한 슬롯에 문장이 2개 이상 몰리면(2026-09-24
     기준 하향 — 기존 "3개 이상") "과다" 상태로 표시한다(아래 3번).
3. **결과를 `narration`에 원문 그대로 쓴다.** 어미를 다듬거나 표현을 소비자 친화적으로 바꾸지 않는다 —
   위 "화면·음성 문장 분리"의 글자수(30자)·재작성 규칙은 여기 적용하지 않는다. 문장·단어를 추가·삭제하지
   않고, 순서도 바꾸지 않는다.
4. **화면용 `headline`/`body`는 그 슬라이드 narration 안에 있는 내용만으로 짧게 요약**한다(대본에 없는
   제품 특징·효과·수치를 붙이지 않는다). headline은 기존 16자 제한을 유지하되, narration 전체를 다
   담으려 하지 말고 핵심만 축약한다 — 축약이 사실을 왜곡하면(예: "미끌거림 없이 씻긴다"를 "완벽 세척"으로
   과장) 안 된다.
   - **`long`(문장 2개 이상 몰림) 슬롯의 화면 문구**(2026-09-24 추가): 위 "재분배"로도 한 슬롯에 문장이
     2개 이상 남으면, `narration`에는 원문 문장을 전부 그대로 유지하되(문장 손실 없음), 화면
     `headline`/`body`는 그중 **가장 핵심적인 문장 하나만** 요약해 담는다 — 두 문장을 이어붙이거나
     `body`에 줄바꿈(`\n`)으로 나눠 둘 다 표시하지 않는다(닥터지 실측: 후기 문장 2개를 `body`에 2줄로
     다 넣어 다른 슬라이드보다 화면이 눈에 띄게 길어짐). 어느 문장이 "핵심"인지는 그 슬롯 역할에 더
     가까운 쪽(예: 상품평 재가공 슬롯이면 구체적 사용감·평가가 담긴 문장)을 우선한다.
   - **`short` 슬롯(그 슬롯에 대응하는 문장이 원문에 없어 narration이 빈 슬롯)의 화면 문구**(2026-09-24
     추가): 인접 슬라이드에 배정된 원문 문장 중 **그 슬롯 역할에 해당하는 절**(원문에 이미 존재하는
     내용, 새로 쓰지 않음)이 있으면, 그 절만 `headline`/`body`로 옮겨 적는다. `narration`은 비워둔다 —
     그 절의 음성은 이미 인접 슬라이드에서 재생되므로 중복 재생하지 않는다(서버 `build_narration()`이
     `script_source=="user"`일 때 narration 필드만 읽고 headline으로 되채우지 않게 되어 있어, 여기서
     headline만 채워도 음성에 새는 일은 없다). 원문에 그 슬롯 역할에 해당하는 내용이 **전혀 없으면**
     (예: 특가/가격 언급 자체가 원문에 없음) 화면도 비워둔다 — 이 경우까지 억지로 채우면 원문에 없는
     제품 특징·효과·수치를 새로 지어내게 된다.
5. `outro`는 비워둔다(위 "마무리 나레이션" 참고). `_SUPPLEMENTS` 등 서버 쪽 자동 보충문장도 붙지 않도록
   completed JSON 최상위에 `"scriptSource": "user"`를 반드시 적는다.
6. **부족/과다/매핑 실패는 조용히 넘기지 않는다.** 아래 스키마의 `qa.scriptMapping`에 슬라이드별로
   원문에서 가져온 범위와 상태(`ok`/`short`/`long`)를 기록한다 — `short`(대응 문장 없음)나 `long`(문장
   과다)이 하나라도 있으면 completed JSON은 그대로 저장하되, STEP3가 이 상태를 사용자에게 보여주고
   수정을 요청할 수 있도록 상태 값을 정확히 남긴다. 이 상태를 근거로 **narration을 임의로 채우거나
   긴 슬롯을 자르지 않는다** — `short` 슬롯의 화면 문구만 위 4번 하위 규칙대로 인접 문장에서 옮길 수
   있고, 그마저 원문에 근거가 없으면 화면도 비워둔다.
7. 원문에 있는 사실 주장(가격·효능·후기 등)도 기존 "근거 기록" 규칙대로 이미지·리뷰와 대조해
   `qa.evidence`/`qa.unverified`에 남긴다. 근거가 없다고 원문을 고치거나 빼지 않는다 — `qa.unverified`에
   기록해 사람이 판단하게 한다.
8. `thumbnailA`/`thumbnailB`는 기존과 동일하게 1번 슬라이드 headline(위 4번에서 만든 화면용 요약)의
   변형 2개로 만든다.

`fullScript`가 없으면 이 섹션은 적용하지 않는다 — 기존 AI 자동 생성 경로(헤드라인 앵글 로테이션 등)를
그대로 따른다.

## 비동기 카피 생성 요청 처리 (pending → completed)

2026-07-09부터 `dashboard.html`은 카피를 직접 계산하지 않는다. STEP2("🚀 파이프라인 실행")를
누르면 서버(`server.py`)가 `public/pending/{requestId}.json`에 요청을 저장하고, 대시보드는
`GET /copy-status?requestId=...`를 폴링하며 기다린다. **이 pending 요청을 실제로 처리해
`public/completed/{requestId}.json`을 만드는 주체가 이 스킬을 참고하는 Claude Code 세션이다.**

**트리거는 두 가지다**:
- **자동(기본)**: `server.py`가 pending 저장 직후 `claude -p`(헤드리스 실행)를 백그라운드로
  자동 호출해 아래 절차를 그대로 수행시킨다 (`_run_headless_copy_worker`, 5분 타임아웃).
  이 경우 이 스킬을 읽는 주체는 사용자가 아니라 그 헤드리스 프로세스 자신이다.
- **수동(폴백)**: 자동 실행이 실패했거나(`claude` CLI 못 찾음/타임아웃/completed 파일 미생성)
  사용자가 직접 "pending 요청 처리해줘"라고 요청한 경우 — 아래 절차를 그대로 따른다.
  자동 실행이 실패해도 pending 파일은 지워지지 않으므로 이어서 처리 가능하다.

1. `shopping-shorts/public/pending/*.json` 을 확인한다. 각 파일은 다음 필드를 담고 있다:
   - `requestId`, `productName`, `partnerLink`, `category`(이미 `resolveFoodCategory` 적용된
     값 — 예: 신선식품이면 `식품_신선`), `productImages`(파일 경로 배열), `reviewImages`(파일
     경로 배열, 비어있을 수 있음), `fullScript`(선택 — 있으면 위 "사용자 제공 완성 대본 처리" 절차를
     따른다. 없으면 이 단계부터는 기존 AI 자동 생성 절차 그대로)
2. `productImages` 파일들을 Read 도구로 직접 열어서 제품의 실제 특징(성분/기능/소재/사용법 등)을
   파악한다 — 카테고리 고정 문구를 베끼지 말고 이미지에서 실제로 보이는 정보를 근거로 쓴다.
3. `reviewImages`가 있으면 파일을 직접 열어서 실제 리뷰 문구·별점을 읽고 5번 슬라이드("상품평
   재가공")에 반영한다. **`reviewImages`가 빈 배열이면 리뷰 인용이나 평점 숫자를 지어내지 않는다**
   — 대신 제품 특징 요약으로 슬롯을 채운다.
4. 위 "카테고리별 7장 슬라이드 구성" 표에서 해당 카테고리의 슬롯 순서를 확인하고, 각 슬롯 역할에
   맞춰 헤드라인/본문을 작성한다 (글자수 제한 준수). 각 슬라이드의 마무리 나레이션(`outro`)도
   위 "마무리 나레이션" 규칙대로 함께 쓴다.
5. 1번 슬라이드(후킹) 헤드라인을 바탕으로 어투·강조점만 살짝 다르게 변형한 2줄짜리 썸네일
   문구 2개(`thumbnailA`/`thumbnailB`)를 만든다 — 새로 지어내는 게 아니라 1번 슬라이드
   카피의 변형이다. 카테고리 고정 문구("○만명이 선택한 ○○템" 같은)는 쓰지 않는다.
6. 위 "근거 기록"을 마친 뒤 결과를 아래 스키마로 `shopping-shorts/public/completed/{requestId}.json`에 저장한다:
   ```json
   {
     "requestId": "...",
     "productName": "...",
     "scriptSource": "user",
     "slides": [
       { "headline": "...", "body": "...", "narration": "...", "outro": "..." },
       ... (카테고리 슬롯 순서대로 정확히 7개, 모든 슬라이드에 outro 포함)
     ],
     "thumbnailA": "...",
     "thumbnailB": "...",
     "qa": {
       "evidence": [
         { "slide": 3, "field": "body", "claim": "...", "source": "review_2", "quote": "상품평 원문 그대로" }
       ],
       "unverified": [],
       "scriptMapping": [
         { "slide": 1, "status": "ok", "sourceSentences": "원문 1번째 문장 그대로" },
         { "slide": 6, "status": "short", "sourceSentences": null, "note": "대본에 특가/가격 언급 없음" }
       ]
     }
   }
   ```
   - `productName`(선택)·`scriptSource`(선택, `"user"` 또는 생략)는 신규 필드다 — 없어도(구버전 completed
     JSON) 서버는 기존과 동일하게 동작한다.
   - `slides[].narration`(선택)은 위 "화면·음성 문장 분리" 참고 — 없으면 서버가 headline으로 폴백한다.
   - `qa.scriptMapping`은 `fullScript` 처리 시에만 채운다(위 "사용자 제공 완성 대본 처리" 6번 참고) —
     일반 AI 생성 모드에서는 생략한다.
   - `qa`는 사람이 대조 검증하기 위한 근거 기록이다 (위 "근거 기록"). 대시보드는 이 필드를 무시하고 화면·음성에도 나가지 않는다.
   - `thumbnailA`/`thumbnailB`는 다른 텍스트 필드와 동일하게 줄바꿈은 `\n`으로 표기한다
     (대시보드가 렌더링 시 `<br>`로 변환한다).
7. 저장 후 대시보드가 3초 이내 폴링으로 자동 감지해 STEP3로 넘어간다 — 별도 알림 불필요.
8. 요청을 처리하지 않기로 했다면(취소) `public/pending/{requestId}.json`과
   `public/pending/{requestId}/`(이미지 폴더)를 삭제해도 되지만, 대시보드의 "취소" 버튼이
   `/cancel-copy-request`로 이미 이 정리를 수행하므로 보통 직접 지울 필요는 없다.
